## 5. 隔离如何证明

1. `assert_paper_runtime` 在配置解析后、凭据/数据库/网络客户端创建前拒绝所有 live 启动；生产 `BridgeClient` 和 TypeScript 生产传输继续硬封禁。
2. 公共网络能力只允许固定域名、固定 REST GET 路径和参数，以及两个公共 WS 路由；不接受重定向、环境代理、签名参数或 API Key Header。paper 不构造私有账户查询客户端。
3. Python 模拟执行每个私有调用入口仍校验不可变 paper 身份；全量测试将网络入口设置为毒丸，使用假 Key，验证只依赖自身 `.env` 和账本，不继承父级/宿主凭据。
4. 将整个新模块复制到 `/private/tmp`，macOS 内核规则禁止全部网络以及原工作树、原主仓库读写。显式 IPv4/IPv6 探针得到 `PERMISSION_DENIED`，旧源码只读探针也被拒绝；同一环境 187 个测试全部通过，离线命令完成 1 笔明确标记的合成交易。
5. 正常公共行情模式不是内核禁网模式，不能混淆两份证据；它依赖公共能力 allowlist 和硬封禁私有客户端。真实服务器 OS 出口/ACL 仍未验收。页面零计数只是可观测状态，不是生产交易所对账证明。

没有访问真实账户去查询“零订单”，因为这也是本轮禁止的私有读取。所有运行产物都在新模块的独立临时副本或测试临时目录；工作树新模块的 logs/reports/trades 仍只有 `.gitkeep`。

## 7. 启动与不能实盘的缺项

最短路径见 [README](../README.md#安装与启动)：安装锁定依赖后 `python main.py --headless`；需要网页则在新 `.env` 设置独立管理令牌后 `python main.py`，访问 `127.0.0.1:8765`。不需要 Binance Key。停止后不会伪造停机期间成交；重启恢复自身 paper 状态。

当前仍不能实盘：

- 生产入口硬封禁，真实独立服务器用户/ACL/网络出口和独立账户 UID 尚未验收。
- 原生止损子订单归属、部分成交/撤单竞态、重启对账、费用/资金费/强平/余额同步未完成生产验收。
- 非空 WAL 异常恢复、长时间压力/断网/磁盘故障验证与足够前向/样本外 paper 统计尚缺；不得通过清 WAL/清库解除。
- 模拟止损不是交易所持有的保护单；滑点/跳空可使实际亏损超过预算，模拟表现不是盈利承诺。

不启动执行桥、不填写旧 Key、不创建验证订单、不修改 `isolation-policy.json` 绕过。完成后续验收并获得单独实盘授权前，继续只跑 PAPER。
